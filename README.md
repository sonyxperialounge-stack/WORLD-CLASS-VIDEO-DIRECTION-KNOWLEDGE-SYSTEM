## Why this exists

Most filmmaking advice is either too vague to act on ("make it cinematic", "use good lighting") or locked inside software tutorials and scattered YouTube videos. This library does something different:

- **Teaches observable decision systems, not taste claims.** Every consequential topic follows a depth contract: purpose → observable inputs → diagnostic questions → options → selection criteria → trade-offs → recommendation → boundary conditions → micro-decisions → failure signatures → correction → verification → dependencies → worked examples → confidence.
- **Bans generic advice.** "Make it cinematic" appears here only as an example of what *not* to write. Where numbers appear (frame timings, loudness targets, reading rates), units and assumptions are stated, and illustrative figures are separated from delivery specifications.
- **Refuses false universals.** Style rules are labelled as context-dependent heuristics. Where aesthetic preference, technical requirement and editorial ethics point in different directions, the library says so.
- **Honest about evidence.** External specifications were verified against primary sources where stated; everything else is labelled unverified or omitted (see [SOURCES-AND-LIMITATIONS.md](SOURCES-AND-LIMITATIONS.md)).

- Every chapter lists its **prerequisites** and **canonical ownership** — mix technique lives in [Mix Strategy](AUDIO/Mix-Strategy.md), loudness targets in [Audio Delivery](DELIVERY/Audio-Delivery.md), caption rules in [Captions and Accessibility](TEXT-ACCESSIBILITY/Captions-and-Accessibility.md), rights and consent in [Rights, Consent and Disclosure](OPERATIONS/Rights-Consent-and-Disclosure.md), export specs in [Quality Control and Export](DELIVERY/Quality-Control-and-Export.md), colour pipeline in [Color Management](COLOR/Color-Management.md). - All examples are **clearly labelled hypothetical**; the four projects' fixed facts live in [Decision Method §7](FOUNDATIONS/Decision-Method.md#7-recurring-hypothetical-projects).
- New to a term? [GLOSSARY.md](GLOSSARY.md) defines each term exactly once and links the owner chapter.
